# 문체 규칙

문체 규칙의 **단일 원본**. 다른 위치(`agent-workspace/AGENT_RULE.md`, `AGENT_RULE_SEED.md`, 폴더별 `AGENT_RULE.md`)는 본문 복제 없이 이 파일을 링크 참조.

- **[최우선] 가운뎃점(`·`, `•`) 절대 금지**
- **[최우선] 콜론(`:`)은 인라인 레이블, 필드명 뒤에만.** 
  - 틀린 예시: "...잘 처리함:" + 코드블록 → 옳은 예시: "...잘 처리함." + 코드블록
  - 틀린 예시: "카테고리별 잔여:" + 불릿 → 옳은 예시: "카테고리별 잔여" + 다음 줄 불릿
  - 틀린 예시: "데이터 인터페이스," + 불릿 → 옳은 예시: "데이터 인터페이스" + 불릿
  - 옳은 예시: "정리하면," + 인라인으로 이어지는 도입구 쉼표
  - 옳은 예시: "이름: `example-name`" 명사형 레이블의 같은 줄에서 인라인 값 도입
  - 출력 전 도입부 콜론 훑어 제거.
- 코드 펜스 블록은 앞뒤로 빈 줄 하나씩.
- 한 소주제는 줄바꿈만 하거나 빈 줄 하나로 덩어리감.
- 맥락이 바뀌는 부분은 빈 줄 두 줄 이상으로 구분.


## 단어 표현

- 도입부 군더더기, 맞장구, 예고 멘트("맞습니다", "정리해서 알려드릴게요", "좋은 질문이다") 없이 바로 본론.
- 더 직접적인 단어 (예: "결국"보다 "따라서").
- "박다/박아둔다/박는다" 틀림. → "등록한다", "반영한다", "기록한다", "추가한다" 옳음.
- 시각적으로 잘 그려지는 단어를 고르되 과한 시각화는 금지.
- 기술 문서, 설명엔 과한 형용사, 부사 금지. 평범한 엔지니어 메모처럼 사실만. 과장 강조, 의인화, 불필요한 볼드는 AI 티.
  - 틀린 예시: "컴파일/링크 에러로 시끄럽게 터짐" → 옳은 예시: "컴파일/링크에서 빌드 실패".
  - 틀린 예시: 잘못 "ESP 가 제 일 했고 들을 사람만 없음" → 옳은 예시: "송신 했으나 받을 대상이 없음."
- 명사형 종결 어미 선호, 부득이할 때만 '~입니다', '~합니다'. 존댓말 우선.

## 문체 자가 점검

기계적으로 검출 가능한 위반은 실제 문자, 패턴을 검색해 확인.("문체 어긋난 데 있나 봐줘" 류 요청 포함).

- 가운뎃점(`·`, `•`), 콜론(`:`)처럼 특정 문자로 잡히는 항목은 직접 grep 해 한 건씩 판정.
