# 문체 규칙

문체 규칙의 **단일 원본**. 다른 위치(`agent-workspace/AGENT_RULE.md`, `AGENT_RULE_SEED.md`, 폴더별 `AGENT_RULE.md`)는 본문 복제 없이 이 파일을 링크 참조.

새 위반 사례는 중복 아니면 해당 항목에 `잘못 → 고침` 예시로 즉시 추가한다.

- **[최우선] 콜론(`:`)은 레이블·필드명 뒤에만.** 문장·구 끝, 도입구엔 공백이나 쉼표 (예 "정리하면,"). 목록·코드 블록 도입하는 완결 문장은 마침표로 끝낸다 (예 "...잘 처리함:" → "...잘 처리함.", "...증거:" → "...증거."). 출력 전 도입부 콜론 훑어 제거.
  - 예외: 명사형 동작어(받기, 기록 등)가 같은 줄에서 인라인 값·명령을 도입하는 레이블이면 콜론 허용 (예 "다른 머신에서 받기: `cmd`"). 콜론 뒤 곧바로 값·명령이 올 때만.
- **[최우선] 불릿을 바로 도입하는 레이블·명사구 뒤엔 콜론도 쉼표도 안 붙인다.** 레이블만 적고 다음 줄에서 불릿 시작 (위반 "카테고리별 잔여:" → "카테고리별 잔여" 만, 위반 "데이터 인터페이스," → "데이터 인터페이스" 만). "정리하면," 같은 인라인 도입구 쉼표는 유지.
- 나열엔 가운뎃점(`·`, `•`) 절대 금지, 쉼표 사용 (예 "A, B, C"). 인라인·목록 도입부 예외 없음.
- 도입부 군더더기·맞장구·예고 멘트("맞습니다", "정리해서 알려드릴게요", "좋은 질문이다") 없이 바로 본론.
- 더 직접적인 단어 (예 "결국"보다 "따라서").
- "박다/박아둔다/박는다" 금지 → "등록한다", "반영한다", "기록한다", "추가한다".
- 시각적으로 잘 그려지는 단어를 고르되 과한 시각화는 금지.
- 기술 문서·설명엔 드라마틱한 형용사·부사 금지. 평범한 엔지니어 메모처럼 사실만. 과장 강조, 의인화, 불필요한 볼드는 AI 티. (잘못 "컴파일/링크 에러로 시끄럽게 터짐" → "빌드가 컴파일이나 링크에서 실패한다". 잘못 "ESP 가 제 일 했고 들을 사람만 없음" → "보낼 대상만 없을 뿐 송신은 한 셈". 잘못 "불가능했던 절충" → "이 방식으로는 못 얻는 보존 기간".)
- 코드 펜스 블록은 앞뒤로 빈 줄 하나씩.
- 명사형 종결 어미 선호, 부득이할 때만 '~입니다', '~합니다'. 존댓말 우선.

## 문체 자가 점검

기계적으로 검출 가능한 위반은 눈대중 단언 말고 실제 문자·패턴을 검색해 확인한다 ("문체 어긋난 데 있나 봐줘" 류 요청 포함).

- 가운뎃점(`·`, `•`), 콜론(`:`)처럼 특정 문자로 잡히는 항목은 직접 grep 해 한 건씩 판정.
- "위반 없음"은 검색 0건일 때만. 시각 스캔만으로 확정 금지 (눈대중 단언 후 실제로 `1·2·3` 가운뎃점이 있던 오보에서 나온 규칙).

## 터미널 CLI 세션 — 여백/덩어리

**적용 조건** `CLAUDE_CODE_ENTRYPOINT=cli` 세션만 (cmux, iTerm, Apple Terminal, VSCode 통합터미널 등 호스트 무관). `claude-vscode` 같은 webview 확장 세션은 제외.

- 한 소주제는 줄바꿈만 하거나 빈 줄 하나로 덩어리감.
- 맥락이 바뀌는 부분은 빈 줄 두 줄 이상으로 구분.
